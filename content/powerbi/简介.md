
# 组成部分

根据你正在整理的 Power BI 笔记，以下是完整的组成部分和工作流程，可以直接延续到你的笔记中：

---

## 组成部分

### 1. Power BI Desktop（桌面版）
- **核心开发工具**，免费下载，用于本地完成全部开发工作
- 包含三大模块：
  - Power Query：数据获取与清洗（M 语言）
  - 数据建模：建立表关系、创建度量值/计算列（DAX 语言）
  - 报表视图：设计可视化图表与页面布局

### 2. Power BI Service（在线服务）
- 云端平台，用于报表发布、共享与协作
- 核心功能：
  - 工作区（Workspace）管理
  - 仪表板（Dashboard）拼接
  - 数据刷新计划
  - 行级安全性（RLS）控制
  - 应用（App）打包分发

### 3. Power BI Mobile（移动端）
- 支持 iOS / Android / Windows 查看报表和仪表板
- 支持移动端布局优化、警报提醒

### 4. Power BI Report Server（报表服务器）
- 本地化部署方案，满足数据不出内网的企业合规需求
- 支持分页报表（Paginated Reports）和桌面版报表

### 5. Power BI Gateway（数据网关）
- 连接本地数据源（本地数据库、Excel、文件等）与云端的桥梁
- 分两种模式：
  - **企业模式（On-premises Gateway）**：多人共用，支持刷新
  - **个人模式（Personal Gateway）**：仅供个人使用

### 6. Power BI Embedded（嵌入式服务）
- 将 Power BI 报表嵌入到第三方应用/网页中，按容量计费

### 7. 其他辅助组件
- **Power BI Report Builder**：创建分页报表
- **Power BI REST API**：以编程方式管理数据源、刷新、权限等
- **DAX Studio / Tabular Editor**：第三方优化与建模工具

---

## 工作流程

### 第一步：数据获取（Get Data）
- 支持连接多种数据源：数据库（SQL Server、MySQL、Oracle）、Excel、CSV、Web、SaaS 应用（Salesforce、SAP）等

### 第二步：数据清洗与转换（Power Query）
- 删除列/行、过滤、去重、拆分、合并、透视/逆透视
- 追加查询、合并查询（类似 SQL JOIN）
- 添加自定义列（M 语言）

### 第三步：数据建模（Data Modeling）
- 建立表间关系（一对多、多对多）
- 创建计算列、度量值（DAX）
- 设置字段格式、排序方式、默认汇总方式
- 创建层次结构（日期层次、地理层次等）

### 第四步：可视化设计（Report）
- 使用可视化控件（柱状图、折线图、地图、矩阵、卡片、切片器等）
- 添加筛选器（页面级、报表级、视觉级）
- 设计报表主题与页面布局

### 第五步：发布与共享（Publish & Share）
- 将 `.pbix` 文件发布到 Power BI Service
- 配置数据刷新计划（Gateway 配合）
- 创建仪表板、分享报表、打包为 App

### 第六步：协作与治理
- 设置访问权限与行级安全性（RLS）
- 数据血缘关系查看（影响分析）
- 设置订阅警报与报表关注

---

**一句话总结**：组成上分为开发（Desktop）、共享（Service）、移动（Mobile）、本地（Report Server）和连接（Gateway）；流程上为 **获取 → 清洗 → 建模 → 可视化 → 发布 → 刷新/治理**。

## M 语言（Power Query）

### 概述
- M 语言是 **Power Query** 中的数据转换语言，用于数据的**获取、清洗和预处理**阶段
- 每次点击界面操作，后台都会自动生成对应的 M 代码

### 核心语法
| 要素 | 说明 | 示例 |
|------|------|------|
| `let` / `in` | 表达式结构，`let` 定义步骤，`in` 返回结果 | `let 源 = ... in 源` |
| 变量赋值 | 用 `=` 赋值，每一步引用上一步结果 | `清洗 = Table.SelectRows(源, ...)` |
| 函数 | 以 `FunctionName(参数)` 形式调用 | `Table.RemoveColumns(表, {"列名"})` |
| 数据类型 | 文本、数字、日期、逻辑值等 | `"文本"`、`123`、`#date(2026,5,26)` |

### 常用函数
| 分类 | 函数示例 |
|------|----------|
| 取数 | `Sql.Database(服务器, 数据库)`、`Excel.Workbook(文件)`、`Web.Contents(URL)` |
| 行列操作 | `Table.SelectRows`、`Table.SelectColumns`、`Table.AddColumn`、`Table.RemoveColumns` |
| 分组聚合 | `Table.Group(表, 分组键, 聚合操作)` |
| 合并/追加 | `Table.NestedJoin`、`Table.Combine` |
| 文本处理 | `Text.Trim`、`Text.Split`、`Text.Replace` |
| 条件判断 | `if ... then ... else ...` |
| 自定义函数 | `(参数) => 表达式` |

```m
let
    源 = Sql.Database("server", "hxnew_center"),
    查询 = 源{[Name="com_base"]}[Data],
    清洗 = Table.SelectRows(查询, each [companyName] <> null),
    新增列 = Table.AddColumn(清洗, "标记", each if [age] > 28 then "VIP" else "普通")
in
    新增列
```

### 特点
- **纯函数式**：每一步不可变，产生新表而非修改原表
- **步骤可见**：查询编辑器右侧会显示每一步操作记录
- **惰性求值**：只在最终使用时才真正计算

## DAX（数据分析表达式）

### 概述
- DAX 是 **数据建模与计算** 的语言，用于创建**度量值、计算列和计算表**
- 基于列上下文和筛选上下文动态计算结果

### 核心语法
| 要素 | 说明 | 示例 |
|------|------|------|
| 度量值 | 用 `=` 定义，写在表下，随筛选条件变化 | `总销售额 = SUM(销售表[金额])` |
| 计算列 | 逐行计算，物理存储在表中 | `年龄 = YEAR(TODAY()) - 用户表[出生年份]` |
| `CALCULATE` | 最核心函数，修改筛选上下文 | `CALCULATE(SUM(销售[金额]), 区域 = "华东")` |
| `FILTER` | 返回满足条件的表 | `FILTER(销售表, 销售表[金额] > 1000)` |
| `ALL` | 忽略筛选器 | `SUM(销售[金额]) / CALCULATE(SUM(销售[金额]), ALL(销售))` |

### 常用函数
| 分类 | 函数示例 |
|------|----------|
| 聚合 | `SUM`、`AVERAGE`、`COUNT`、`COUNTROWS`、`DISTINCTCOUNT` |
| 筛选 | `CALCULATE`、`FILTER`、`ALL`、`ALLSELECTED`、`VALUES` |
| 时间智能 | `TOTALYTD`、`SAMEPERIODLASTYEAR`、`DATEADD`、`DATESINPERIOD` |
| 逻辑 | `IF`、`SWITCH`、`AND`、`OR`、`ISBLANK` |
| 关系 | `RELATED`（多端取一端）、`RELATEDTABLE`（一端取多端） |
| 文本 | `FORMAT`、`CONCATENATE`、`LEFT`、`RIGHT` |
| 迭代器 | `SUMX`、`AVERAGEX`、`MAXX`（逐行计算后聚合） |
| 上下文 | `EARLIER`、`ROW`、`KEEPFILTERS` |

```dax
-- 年度累计销售额
年累计 = TOTALYTD(SUM(销售表[金额]), 日期表[日期])

-- 上月同期
上月同比 = CALCULATE(SUM(销售表[金额]), SAMEPERIODLASTYEAR(日期表[日期]))

-- 占比（占总计百分比）
占比 = DIVIDE(SUM(销售表[金额]), CALCULATE(SUM(销售表[金额]), ALL(销售表)))

-- 动态排名
排名 = RANKX(ALL(产品表[产品名称]), SUM(销售表[金额]))

-- 条件判断
客户等级 = IF(SUM(销售表[金额]) > 100000, "A级客户", "普通客户")
```

### 核心概念
| 概念 | 说明 |
|------|------|
| 筛选上下文 | 外部筛选器（切片器、报表筛选）对计算结果的影响 |
| 行上下文 | 迭代/计算列中当前行的上下文 |
| 上下文转换 | `CALCULATE` 将行上下文转换为筛选上下文 |
| 扩展表 | 筛选通过表关系沿一端向多端传播 |

### 度量值 vs 计算列
| 对比项 | 度量值 | 计算列 |
|--------|--------|--------|
| 计算时机 | 查询时动态计算 | 刷新时物理存储 |
| 存储空间 | 不占空间 | 占用模型空间 |
| 随筛选变化 | 会动态变化 | 固定不变 |
| 适用场景 | 报表展示指标 | 切片、行级过滤 |

## 两者对比总结

| 对比项 | M 语言 | DAX |
|--------|--------|-----|
| 所处阶段 | 数据获取与清洗（ETL） | 数据建模与计算 |
| 所在工具 | Power Query 编辑器 | 报表视图/数据视图 |
| 执行时机 | 刷新数据时 | 报表交互时 |
| 操作对象 | 表、列（行级操作） | 表（列/值，受筛选影响） |
| 核心机制 | 步骤式管道（let...in） | 上下文（筛选/行） |
| 结果 | 生成一张新表 | 返回一个值或一张表 |
| 类比 SQL | `SELECT` + 各种函数 | `GROUP BY` + 聚合 + 子查询 |

**一句话总结**：**M 管"表怎么洗干净"**，**DAX 管"指标怎么算出来"**；前者在数据入模型之前处理，后者在模型内根据用户交互动态计算。
